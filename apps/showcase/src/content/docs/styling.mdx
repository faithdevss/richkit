`@richkitjs/react` ships **no CSS**. `EditorContent` renders a plain wrapper div and
mounts ProseMirror's own DOM into it — you write the stylesheet.

## What you get to style

- **`.ProseMirror`** — the actual content-editable root ProseMirror mounts. Your
  paragraph/heading/list/table styles go here, scoped under this class.
- **`.toolbar`, `.tb-group`, `.tb-btn`, `.is-active`** — fixed class names baked into
  `Toolbar`, `ToolbarGroup`, and `ToolbarButton` from `@richkitjs/react`. Style these
  directly; they're not renamed per-project.
- **`EditorContent` and `BubbleMenu`** accept a `className` prop with no default —
  whatever you pass is the only hook, so name it yourself.

```css
.ProseMirror {
  min-height: 300px;
  outline: none;
  padding: 16px;
}
.ProseMirror p {
  margin: 0 0 12px;
}
.tb-btn.is-active {
  background: #eef2ff;
}
```

## Borrowing the editors stylesheet

Don't want to write it all? `@richkitjs/editors/style.css` is the stylesheet behind the
[ready-made editors](/docs/api/editors), and its rules are not tied to those
components. Import it and your own `@richkitjs/react` UI is styled too — toolbar
(`.toolbar`, `.tb-btn`), menus and popovers, `.bubble-menu`, slash and mention menus,
block handle, sidebars, modals, toasts and the content itself (`.editor .ProseMirror`):

```tsx
import '@richkitjs/editors/style.css'

<Toolbar editor={editor} className="toolbar">{/* ... */}</Toolbar>
<EditorContent editor={editor} className="editor" />
<BubbleMenu editor={editor} className="bubble-menu">{/* ... */}</BubbleMenu>
```

Note the content rules are scoped under `.editor`, so give `EditorContent` that class.
Every colour, radius and shadow in it is a CSS variable, prefixed so it never clashes
with your app's tokens (`--rk-bg`, `--rk-surface`, `--rk-surface-2`, `--rk-border`,
`--rk-border-strong`, `--rk-text`, `--rk-text-muted`, `--rk-accent`, `--rk-accent-soft`,
`--rk-accent-hover`, `--rk-danger`, `--rk-radius`, `--rk-radius-sm`, `--rk-radius-lg`,
`--rk-shadow-sm/md/lg`), light on `:root` and dark under `[data-theme='dark']` — override
those to rebrand. The full table is in
[Ready-made editors → Styling](/docs/api/editors#styling).

## Theming with CSS custom properties

Every live example on this site (the [usecases](/docs/usecases/agent-workflows)) is
styled this way, but it's a convention you can adopt in your own app — the library
doesn't require it. Define a small palette as custom properties, then flip them per
container with a `data-theme` attribute:

```css
[data-theme='light'] {
  --rk-bg: #f5f6f8;
  --rk-surface: #ffffff;
  --rk-border: #e3e6ea;
  --rk-text: #1a1d21;
  --rk-accent: #2563eb;
}
[data-theme='dark'] {
  --rk-bg: #0c0c0e;
  --rk-surface: #17171a;
  --rk-border: #2a2a2f;
  --rk-text: #ececee;
  --rk-accent: #7c8bff;
}
```

```tsx
<div data-theme="dark">
  <Toolbar editor={editor}>{/* ... */}</Toolbar>
  <EditorContent editor={editor} className="editor" />
</div>
```

Because `[data-theme='dark']` is a plain attribute selector, it applies to whichever
element carries the attribute — put it on a wrapper div and everything inside picks up
the palette. Switch it with state to support a light/dark toggle.

## Reference implementation

This site's own `apps/showcase/src/editor-base.css` and `showcase.css` are a complete,
working example of the pattern above — copy the variable list and `.ProseMirror`
rules as a starting point rather than writing a theme from scratch.
