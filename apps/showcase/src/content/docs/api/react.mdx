# API: React components (`@richkitjs/react`)

Every exported component and its props. All of them take `editor` — most tolerate
`Editor | null` so you can render before the hook resolves, but a few require a live
editor and must be guarded.

## `useEditor`

```tsx
const editor = useEditor(options, deps)
```

| Param     | Type                     | Default | Description                                                                                 |
| --------- | ------------------------ | ------- | ------------------------------------------------------------------------------------------- |
| `options` | `EditorOptions`          | —       | Same object the [`Editor` constructor](/docs/api/editor) takes. Omit `element`.             |
| `deps`    | `ReadonlyArray<unknown>` | `[]`    | Recreates the editor when these change. Leave empty unless you truly want a fresh instance. |

Returns `Editor | null` — **`null` on the first render**, since the instance is created in
an effect. Guard before use:

```tsx
const editor = useEditor({ extensions: StarterKit, content: '<p>Hi</p>' })
if (!editor) return null
```

Options are read from a ref, so changing them after mount does **not** rebuild the editor;
only `deps` does. The hook re-renders on `update` and `selectionUpdate`, which is what
keeps toolbar active-states in sync.

Event handlers are re-pointed at each render, so `onUpdate` and friends always see current
props and state — no stale closures, and no need to list state in `deps`:

```tsx
const [docId, setDocId] = useState('a')
const editor = useEditor({
  extensions: StarterKit,
  onUpdate: ({ editor }) => save(docId, editor.getHTML()), // always the current docId
})
```

Putting state in `deps` would destroy and rebuild the editor on every change, losing
content, selection, and undo history. Reserve `deps` for genuinely switching documents.

## `useControlledEditor`

`useEditor` with the contract of a form input: `value`/`defaultValue` in, `onChange`
out, in the format your app stores. It is what every
[ready-made editor](/docs/api/editors) is built on.

```tsx
import { useControlledEditor, EditorContent } from '@richkitjs/react'
import { StarterKit } from '@richkitjs/starter-kit'

function MyEditor({ value, onChange }: { value: string; onChange: (html: string) => void }) {
  const editor = useControlledEditor({ extensions: StarterKit, value, onChange })
  return <EditorContent editor={editor} />
}
```

Takes every [`EditorOptions`](/docs/api/editor) field except `content` and `editable`,
plus:

| Option         | Type                                       | Default  | Description                                                                                     |
| -------------- | ------------------------------------------ | -------- | ----------------------------------------------------------------------------------------------- |
| `value`        | `EditorValue<F>`                           | —        | The content, in `format`. Passing it makes the editor controlled.                               |
| `defaultValue` | `EditorValue<F>`                           | —        | Starting content for an uncontrolled editor.                                                    |
| `onChange`     | `(value: EditorValue<F>) => void`          | —        | Called with the new content, in `format`, after every edit.                                     |
| `format`       | `'html' \| 'markdown' \| 'text' \| 'json'` | `'html'` | Shape of `value` and `onChange`. `EditorValue<'json'>` is `JSONContent`; the rest are `string`. |
| `disabled`     | `boolean`                                  | `false`  | Read-only. Your component styles it as disabled.                                                |
| `readOnly`     | `boolean`                                  | `false`  | Read-only.                                                                                      |

Second argument: `deps`, as for `useEditor`. Returns `Editor | null`.

- A `value` the editor itself just emitted is not written back, so typing never resets
  the caret.
- Any other `value` (a form reset, a loaded record) replaces the document **without**
  firing `onChange` and **without** landing on the undo stack.
- `disabled` / `readOnly` flip the live editor instead of rebuilding it.
- An empty document reads as `''` in the string formats, not `<p></p>`.
- Your own `onUpdate` still runs, after `onChange`.

### `getEditorValue` / `toEditorContent`

The conversions `useControlledEditor` uses, for when you read or write values yourself.

```ts
getEditorValue(editor, 'markdown') // current doc as Markdown ('' when empty)
editor.setContent(toEditorContent(md, 'markdown'))
```

| Function                         | Returns                 | Description                                                                                                                             |
| -------------------------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `getEditorValue(editor, format)` | `EditorValue<format>`   | The document as HTML, Markdown, plain text (one line per block) or JSON.                                                                |
| `toEditorContent(value, format)` | `string \| JSONContent` | Turns a value in `format` into content `Editor` accepts: Markdown → HTML, text → one `<p>` per line (escaped), HTML and JSON unchanged. |

Types: `ValueFormat` (`'html' | 'markdown' | 'text' | 'json'`), `EditorValue<F>` and
`JSONContent` (a ProseMirror document as plain JSON).

## `RichViewer`

Read-only display of stored content, with no editor mounted. Unsafe tags, attributes and
URLs are removed on the way in. See [Sanitizing & viewing HTML](/docs/sanitize).

```tsx
<RichViewer className="editor" extensions={StarterKit} content={post.html} />
```

| Prop         | Type                             | Description                                                    |
| ------------ | -------------------------------- | -------------------------------------------------------------- |
| `content`    | `string \| JSONContent \| null`  | `getHTML()` / `getJSON()` output, or any HTML.                 |
| `extensions` | `AnyExtension[]`                 | The extensions the content was written with. Or pass `schema`. |
| `schema`     | `Schema`                         | An existing schema, such as `editor.schema`.                   |
| `document`   | `Document`                       | A DOM for server rendering.                                    |
| `...rest`    | `HTMLAttributes<HTMLDivElement>` | Forwarded to the wrapper, which always has `richkit-viewer`.   |

`sanitizeHtml` and `renderHtml` are re-exported from `@richkitjs/html` for convenience.

### `buildMenus(editor, actions?)`

Returns the default menu set — **File, Edit, View, Insert, Format, Tools, Table,
Help** — as `MenuDef[]`. Filter or extend it before passing it to `Menubar`:

```tsx
const menus = buildMenus(editor, { findReplace: () => setFindOpen(true) })
  .filter((m) => ['Edit', 'Insert', 'Format'].includes(m.label))

<Menubar editor={editor} menus={menus} />
```

Items that open app UI need a callback from you; without one they render disabled.
`MenuActions`:

| Action               | Type         | Menu item it powers                                                                                      |
| -------------------- | ------------ | -------------------------------------------------------------------------------------------------------- |
| `findReplace`        | `() => void` | Edit → Find and replace…. Open a [`FindReplace`](#modals) modal.                                         |
| `sourceCode`         | `() => void` | View → Source code and Tools → Source code. Open a [`SourceCode`](#modals) modal.                        |
| `restoreDraft`       | `() => void` | File → Restore last draft.                                                                               |
| `importFile`         | `() => void` | File → Import file….                                                                                     |
| `wordCount`          | `() => void` | Tools → Word count.                                                                                      |
| `shortcuts`          | `() => void` | Help → Keyboard shortcuts.                                                                               |
| `toggleSpellcheck`   | `() => void` | Tools → Spellcheck. `spellcheckOn?: boolean` sets its checkmark.                                         |
| `addComment`         | `() => void` | Insert → Comment.                                                                                        |
| `toggleOutline`      | `() => void` | View → Outline panel and Insert → Table of contents. `outlineOpen?: boolean` sets the checkmark.         |
| `toggleComments`     | `() => void` | View → Comments panel. `commentsOpen?: boolean` sets its checkmark.                                      |

## Notifications

Mount `<NotificationsHost />` once near your app root. Its one prop:

| Prop         | Type         | Description                                                                                                                                                       |
| ------------ | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `uploadFile` | `UploadFile` | Stores images and files users upload from the toolbar, menubar, slash menu and image dialog, resolving to their URL. Without it they are inlined as `data:` URLs. |

Then call `notify` from anywhere:

```tsx
notify.toast.success('Saved')
const id = notify.toast.info('Uploading…', { durationMs: 10_000 })
notify.toast.dismiss(id)

const name = await notify.prompt({ title: 'Rename', defaultValue: 'Untitled' })
const ok = await notify.confirm({ title: 'Delete this?', destructive: true })
await notify.alert({ title: 'Export finished' })
```

Toasts live under `notify.toast` (`info`, `success`, `warn`, `error`, `dismiss`); dialogs
are on `notify` directly.

| Dialog           | Options                                                                                                  | Resolves to                                  |
| ---------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `notify.prompt`  | `title`, `message?`, `placeholder?`, `defaultValue?`, `okLabel?`, `cancelLabel?`, `required?`, `anchor?` | `string \| null` (null on cancel)            |
| `notify.confirm` | `title`, `message?`, `okLabel?`, `cancelLabel?`, `destructive?` (red OK button)                          | `boolean`                                    |
| `notify.alert`   | `title`, `message?`, `okLabel?`                                                                          | `void`                                       |
| `notify.image`   | `title?`, `uploadFile?`, `defaultTab?: 'upload' \| 'link'`, `anchor?`                                    | `{ src, alt } \| null`                       |
| `notify.link`    | `editor` (required), `anchor?`                                                                           | `void` — edits the link in the editor itself |

`anchor` floats the dialog under a spot instead of centring it as a modal. Pass an
element, or `selectionAnchor(editor, pos?)` to anchor at the selection (or at `pos`):

```ts
const body = await notify.prompt({ title: 'Comment', anchor: selectionAnchor(editor) })
const image = await notify.image({ anchor: selectionAnchor(editor) })
if (image) editor.chain().call('insertImage', image).focus().run()
```

Toast calls take `(message: string, { durationMs? })` and return an id for
`notify.toast.dismiss(id)`.

Without a mounted `NotificationsHost`, toasts fall back to `console` and dialogs resolve
to their default (`prompt` → `defaultValue ?? null`, `confirm` → `false`, `image` →
`null`).

## Uploads

```ts
type UploadFile = (file: File) => Promise<string>
```

An `UploadFile` stores a file the user picked and resolves to the URL to put in the
document. Give one to `NotificationsHost` and every insert path (toolbar, menubar, slash
menu, image dialog) uses it; a `uploadFile` prop on a single component overrides it
there.

```tsx
<NotificationsHost
  uploadFile={async (file) => {
    const body = new FormData()
    body.append('file', file)
    const res = await fetch('/api/uploads', { method: 'POST', body })
    return (await res.json()).url
  }}
/>
```

With no uploader, files up to 10 MB are inlined as `data:` URLs (the document grows by
the file's size); larger ones are refused with a toast. If the uploader throws, the user
sees an error toast and nothing is inserted.

`storeFile(file, uploadFile?)` runs that same logic for your own file inputs and
resolves to the URL, or `null` when nothing should be inserted.

## `printEditor`

```ts
printEditor(editor, { title: 'My document', extraCss: '@page { margin: 2cm }' })
```

| Option     | Type     | Description                         |
| ---------- | -------- | ----------------------------------- |
| `title`    | `string` | Document title in the print dialog. |
| `extraCss` | `string` | CSS injected into the print window. |

Opens the browser print dialog with only the document, styled for paper.

## `Icons`

The 18px stroke icons the toolbars use, as React components. Each takes any SVG prop
(`width`, `className`, `strokeWidth`…) and inherits `currentColor`.

```tsx
import { Icons } from '@richkitjs/react'

;<ToolbarButton
  editor={editor}
  command="toggleBold"
  isActiveName="bold"
  label={<Icons.BoldIcon />}
/>
```
