# API: React components (`@richkitjs/react`)

Every exported component and its props. All of them take `editor` — most tolerate
`Editor | null` so you can render before the hook resolves, but a few require a live
editor and must be guarded.

## `useEditor`

```tsx
const editor = useEditor(options, deps)
```

| Param     | Type                     | Default | Description                                                                                 |
| --------- | ------------------------ | ------- | ------------------------------------------------------------------------------------------- |
| `options` | `EditorOptions`          | —       | Same object the [`Editor` constructor](/docs/api/editor) takes. Omit `element`.             |
| `deps`    | `ReadonlyArray<unknown>` | `[]`    | Recreates the editor when these change. Leave empty unless you truly want a fresh instance. |

Returns `Editor | null` — **`null` on the first render**, since the instance is created in
an effect. Guard before use:

```tsx
const editor = useEditor({ extensions: StarterKit, content: '<p>Hi</p>' })
if (!editor) return null
```

Options are read from a ref, so changing them after mount does **not** rebuild the editor;
only `deps` does. The hook re-renders on `update` and `selectionUpdate`, which is what
keeps toolbar active-states in sync.

Event handlers are re-pointed at each render, so `onUpdate` and friends always see current
props and state — no stale closures, and no need to list state in `deps`:

```tsx
const [docId, setDocId] = useState('a')
const editor = useEditor({
  extensions: StarterKit,
  onUpdate: ({ editor }) => save(docId, editor.getHTML()), // always the current docId
})
```

Putting state in `deps` would destroy and rebuild the editor on every change, losing
content, selection, and undo history. Reserve `deps` for genuinely switching documents.

## `EditorContent`

The editable surface. Props extend `HTMLAttributes<HTMLDivElement>`, so `className`,
`style`, `onKeyDown` and friends all pass through to the wrapper div.

| Prop      | Type                             | Description                                        |
| --------- | -------------------------------- | -------------------------------------------------- |
| `editor`  | `Editor \| null`                 | The instance. Nothing renders until it's non-null. |
| `...rest` | `HTMLAttributes<HTMLDivElement>` | Forwarded to the container.                        |

## `EditorProvider` / `useEditorContext`

| Prop       | Type             | Description               |
| ---------- | ---------------- | ------------------------- |

| `children` | `ReactNode`      | —                         |

`useEditorContext()` returns `Editor | null`. Useful for deep toolbars that would
otherwise thread `editor` through every level.

## Toolbar

### `Toolbar`

| Prop        | Type             | Default | Description                                                                   |
| ----------- | ---------------- | ------- | ----------------------------------------------------------------------------- |
| `editor`    | `Editor \| null` | —       | —                                                                             |
| `children`  | `ReactNode`      | —       | Your buttons and groups.                                                      |
| `className` | `string`         | —       | —                                                                             |
| `overflow`  | `boolean`        | `true`  | Keep the row on one line, moving whatever does not fit into a "more" popover. |

The row re-measures on resize, so buttons come back as soon as there is room —
this is what keeps the toolbar to a single line on a phone. Pass
`overflow={false}` to wrap instead.

### `ToolbarGroup`

Layout wrapper for visually grouping buttons. Takes `children` only.

### `ToolbarButton`

| Prop            | Type             | Default | Description                                                                                                         |
| --------------- | ---------------- | ------- | ------------------------------------------------------------------------------------------------------------------- |
| `editor`        | `Editor \| null` | —       | —                                                                                                                   |
| `command`       | `string`         | —       | **Required.** Name of the command to run, e.g. `'toggleBold'`.                                                      |
| `args`          | `unknown[]`      | `[]`    | Arguments passed to the command, e.g. `[{ level: 2 }]`.                                                             |
| `label`         | `ReactNode`      | —       | **Required.** Button content — text or an icon.                                                                     |
| `isActiveName`  | `string`         | —       | Mark/node name used for the active state. Often differs from the command: command `toggleBold`, active name `bold`. |
| `isActiveAttrs` | `Attrs \| null`  | —       | Attribute match for the active state, e.g. `{ level: 2 }`.                                                          |
| `title`         | `string`         | —       | Tooltip / accessible name.                                                                                          |
| `className`     | `string`         | —       | —                                                                                                                   |

```tsx
<ToolbarButton editor={editor} command="toggleBold" isActiveName="bold" label={<Icons.BoldIcon />} title="Bold" />
<ToolbarButton editor={editor} command="setHeading" args={[{ level: 2 }]} isActiveName="heading" isActiveAttrs={{ level: 2 }} label="H2" />
```

### `DefaultToolbar`

| Prop       | Type      | Default | Description                                             |
| ---------- | --------- | ------- | ------------------------------------------------------- |
| `editor`   | `Editor`  | —       | **Non-nullable.** Guard on `editor` before rendering.   |
| `overflow` | `boolean` | `true`  | Same collapsing behaviour, applied to each of its rows. |

A prebuilt toolbar covering the StarterKit commands — no other props, no slots. For a
custom set, compose `Toolbar` + `ToolbarButton` yourself.

## Notifications

Mount `<NotificationsHost />` once near your app root — it takes no props. Then call
`notify` from anywhere:

```tsx
notify.toast.success('Saved')
const id = notify.toast.info('Uploading…', { durationMs: 10_000 })
notify.toast.dismiss(id)

const name = await notify.prompt({ title: 'Rename', defaultValue: 'Untitled' })
const ok = await notify.confirm({ title: 'Delete this?', destructive: true })
await notify.alert({ title: 'Export finished' })
```

Toasts live under `notify.toast` (`info`, `success`, `warn`, `error`, `dismiss`); dialogs
are on `notify` directly.

| Dialog           | Options                                                                                       | Resolves to      |
| ---------------- | --------------------------------------------------------------------------------------------- | ---------------- |
| `notify.prompt`  | `title`, `message?`, `placeholder?`, `defaultValue?`, `okLabel?`, `cancelLabel?`, `required?` | `string \| null` |
| `notify.confirm` | `title`, `message?`, `okLabel?`, `cancelLabel?`, `destructive?`                               | `boolean`        |
| `notify.alert`   | `title`, `message?`, `okLabel?`                                                               | `void`           |

Without a mounted `NotificationsHost`, toasts fall back to `console` and dialogs resolve
to their default (`prompt` → `defaultValue ?? null`, `confirm` → `false`).
