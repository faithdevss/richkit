# API: Ready-made editors

Fourteen finished editors — toolbar, menus, dialogs and styling included. Each one
behaves like a form input: `value` in, `onChange` out. Use them when you want an editor
on the page today; drop down to [`@richkitjs/react`](/docs/api/react) when you need to
build your own chrome.

Six are free, in `@richkitjs/editors` (MIT). Eight are
[RichKit Pro](/docs/licensing), in `@richkitjs/editors-pro`: `SimpleEditor`, `NotionEditor`,
`ClassicEditor`, `QuestionEditor`, `DocxEditor`, `CommentsEditor`,
`TrackChangesEditor` and `AgentEditor`. Both share the stylesheet,
`NotificationsHost` and every prop below. Pro editors run without a key on
localhost; in production, pass your key as the `licenseKey` prop below, or
register it once with [`setLicenseKey`](/docs/licensing).

## Setup

Two one-time steps:

```tsx
// 1. The stylesheet — once, anywhere in your app's entry.
import '@richkitjs/editors/style.css'

// 2. The dialog host — once, near your app root.
import { NotificationsHost } from '@richkitjs/editors'

export function App() {
  return (
    <>
      <Routes />
      <NotificationsHost />
    </>
  )
}
```

The link, image, prompt and confirm dialogs and all toasts render through
`NotificationsHost`. Without it the editors still work, but dialogs resolve to their
defaults (a link prompt returns nothing, a confirm returns `false`) and toasts go to the
console. Pass it `uploadFile` to store uploaded images on your server instead of inlining
them as `data:` URLs — see [`NotificationsHost`](/docs/api/react#notifications).

```tsx
import { useState } from 'react'
import { MinimalEditor } from '@richkitjs/editors'

function PostForm() {
  const [body, setBody] = useState('<p>Hello</p>')
  return <MinimalEditor value={body} onChange={setBody} placeholder="Write something…" />
}
```

## Shared props — `EditorFieldProps`

Every editor except `QuestionEditor` accepts all of these, on top of its own props
listed further down. They are the contract of a form input, so an editor drops into a
plain `useState`, a native `<form>`, react-hook-form's `Controller` (`{...field}` spreads
straight on) or Formik without glue code.

| Prop            | Type                                            | Default    | Description                                                                                                                                                                          |
| --------------- | ----------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `value`         | `string`, or `JSONContent` when `format="json"` | —          | The content, in `format`. Passing it makes the editor **controlled**: the editor shows exactly this, and you update it from `onChange`.                                              |
| `defaultValue`  | same as `value`                                 | —          | Starting content for an **uncontrolled** editor. Read once on mount; later changes are ignored. Use either `value` or `defaultValue`, not both.                                      |
| `onChange`      | `(value) => void`                               | —          | Called with the new content, in `format`, after every edit the user makes. An empty document reads as `''` (not `<p></p>`), so required and dirty checks behave like a `<textarea>`. |
| `format`        | `'html' \| 'markdown' \| 'text' \| 'json'`      | `'html'`   | Shape of `value`, `defaultValue` and `onChange`. `MarkdownEditor` defaults to `'markdown'`. See [Value formats](#value-formats).                                                     |
| `onFocus`       | `() => void`                                    | —          | The editable area gained focus.                                                                                                                                                      |
| `onBlur`        | `() => void`                                    | —          | The editable area lost focus. Form libraries use this to mark a field as touched.                                                                                                    |
| `name`          | `string`                                        | —          | Renders a hidden `<input name={name}>` holding the current value, so a native form submit (or `FormData`) carries it. JSON values are stringified.                                   |
| `disabled`      | `boolean`                                       | `false`    | Not editable, and styled as disabled. Sets `aria-disabled` on the editable element. Toggles the live editor — content, selection and undo history are kept.                          |
| `readOnly`      | `boolean`                                       | `false`    | Not editable, but looks normal — for showing a saved document. Also toggles in place.                                                                                                |
| `autoFocus`     | `boolean`                                       | `false`    | Puts the caret in the editor when it mounts.                                                                                                                                         |
| `placeholder`   | `string`                                        | varies     | Grey text shown while the document is empty. Replaces the editor's built-in placeholder.                                                                                             |
| `theme`         | `'light' \| 'dark'`                             | per editor | Colour scheme (see the table above). Editors with a theme toggle (`SimpleEditor`, `NotionEditor`, `DocxEditor`) start from it and follow it when it changes.                         |
| `className`     | `string`                                        | —          | Added to the editor's root element, next to its built-in classes.                                                                                                                    |
| `style`         | `CSSProperties`                                 | —          | Inline style on the root element — set a `height`, or override [CSS variables](#styling).                                                                                            |
| `aria-label`    | `string`                                        | —          | Accessible name on the editable element. Give one whenever there is no visible label.                                                                                                |
| `aria-invalid`  | `boolean`                                       | —          | Marks the editable element invalid for screen readers. `ClassicEditor` sets it from `error` unless you pass it.                                                                      |
| `onEditorReady` | `(editor: Editor) => void`                      | —          | Called once with the live [`Editor`](/docs/api/editor) after mount (again only if the editor is rebuilt). Use it for commands the UI does not expose.                                |
| `ref`           | `Ref<EditorHandle>`                             | —          | Imperative handle — see below.                                                                                                                                                       |

### How `value` syncs

- When `value` is just the editor's own `onChange` coming back, nothing happens — the
  caret does not jump while typing.
- When the parent sets a **different** `value` (a form reset, a loaded record), the
  editor replaces its content. This does **not** fire `onChange` and is **not** added to
  the undo history, so <kbd>Mod+Z</kbd> cannot undo a reset.
- Changing `disabled`, `readOnly` or `value` never rebuilds the editor. Changing
  `placeholder` (or props that switch extensions, like `NotionEditor`'s `ai`) does
  rebuild it, keeping the current content.

### Value formats

| `format`     | `value` type  | What you get                                                                                                                         |
| ------------ | ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `'html'`     | `string`      | `editor.getHTML()`. The default, and the lossless string format.                                                                     |
| `'markdown'` | `string`      | CommonMark/GFM via `@richkitjs/markdown`. Anything Markdown cannot express (colours, alignment, comments) is dropped on the way out. |
| `'text'`     | `string`      | Plain text, one line per block. Incoming text becomes one paragraph per line.                                                        |
| `'json'`     | `JSONContent` | `editor.getJSON()` — the ProseMirror document. Lossless; store it in a JSON column.                                                  |

The props are generic over `format`, so TypeScript narrows for you:

```tsx
<MinimalEditor value={html} onChange={(v) => setHtml(v)} />                // v: string
<MinimalEditor format="json" value={doc} onChange={(v) => setDoc(v)} />    // v: JSONContent
```

## `EditorHandle` (the `ref`)

A `ref` on any editor (except `QuestionEditor`, [below](#questioneditor)) gets:

| Member     | Type              | Description                                                                                                                                             |
| ---------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `editor`   | `Editor \| null`  | The live editor; `null` before mount.                                                                                                                   |
| `focus`    | `() => void`      | Focuses the editable area. Form libraries call this to focus the first invalid field.                                                                   |
| `blur`     | `() => void`      | Removes focus.                                                                                                                                          |
| `getValue` | `() => value`     | Current content in `format`.                                                                                                                            |
| `setValue` | `(value) => void` | Replaces the content like a new `value` would. Does **not** fire `onChange`, so use it on uncontrolled editors; a controlled one should change `value`. |
| `clear`    | `() => void`      | Empties the document and fires `onChange` with `''`, as if the user had.                                                                                |

```tsx
const ref = useRef<EditorHandle>(null)

<MinimalEditor ref={ref} defaultValue="" />
<button onClick={() => ref.current?.clear()}>Clear</button>
```

## Forms

### react-hook-form

```tsx
<Controller
  name="description"
  control={control}
  rules={{ required: 'Write a description' }}
  render={({ field, fieldState }) => (
    <ClassicEditor
      {...field}
      label="Description"
      required
      error={!!fieldState.error}
      helperText={fieldState.error?.message}
    />
  )}
/>
```

`field` supplies `value`, `onChange`, `onBlur`, `name`, `disabled` and `ref`; the ref's
`focus()` is what makes focus-on-error work.

### Native forms

```tsx
<form action="/posts" method="post">
  <MinimalEditor name="body" defaultValue="" />
  <button>Save</button>
</form>
```

## Editor-specific props

Each section lists only the props that editor adds to the shared ones.

### `MinimalEditor`

Paragraphs with bold, italic and links, from a bubble menu that appears over a
selection. No toolbar, no headings or lists — for comments, captions and short fields.
Extensions: `Paragraph`, `Bold`, `Italic`, `Link`, `History`.

No extra props.

### `SimpleEditor`

The full StarterKit behind a single toolbar row: undo/redo, block type, bullet and
numbered lists, to-do list, blockquote, code block, bold/italic/strike/code/underline,
highlight, link, super- and subscript, alignment, image, find and replace, and a
light/dark toggle. Buttons that do not fit collapse into a "more" menu. Typing `/`
opens the slash menu, and selecting text shows a bubble menu.

No extra props.

### `ClassicEditor`

A labelled form control in the shape of a Material UI text field: label, menubar over a
full toolbar, the editor, helper text. Default `placeholder`:
`'Type or paste your content here!'`.

| Prop         | Type        | Default                                | Description                                                                                                                                                            |
| ------------ | ----------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `label`      | `ReactNode` | —                                      | Shown above the field. Also labels the editable element (`aria-labelledby`) unless you pass `aria-label`.                                                              |
| `helperText` | `ReactNode` | —                                      | Shown below the field. Turns red with `error` — put the validation message here.                                                                                       |
| `error`      | `boolean`   | `false`                                | Invalid state: red label, border and helper text, and `aria-invalid`.                                                                                                  |
| `required`   | `boolean`   | `false`                                | Adds an asterisk to the label and `aria-required` to the editable element. It does not validate by itself — check the value in your form.                              |
| `menus`      | `string[]`  | `['Edit', 'Insert', 'Format', 'Help']` | Which menubar menus to show, by label. Available: `'File'`, `'Edit'`, `'View'`, `'Insert'`, `'Format'`, `'Tools'`, `'Table'`, `'Help'`. Pass `[]` to hide the menubar. |

See the [Classic editor use case](/docs/usecases/classic-editor) for a full walkthrough.

### `NotionEditor`

A Notion-style page: block handle with drag-to-reorder, `/` commands with a "Recent"
section, `@` mentions, a two-row selection bubble, find and replace (<kbd>Mod+F</kbd>
while focus is inside), an outline rail, word count and a theme toggle.

| Prop            | Type                 | Default | Description                                                                                                                                                                                                                                                                                                                                                           |
| --------------- | -------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `header`        | `ReactNode`          | —       | Left side of the top bar — a breadcrumb or page title.                                                                                                                                                                                                                                                                                                                |
| `headerActions` | `ReactNode`          | —       | Right side of the top bar, after undo/redo and the theme toggle — share buttons, avatars.                                                                                                                                                                                                                                                                             |
| `mentions`      | `MentionCandidate[]` | —       | People and pages offered after `@`. Without it `@` is plain text. `MentionCandidate` is `{ id, label, kind?: 'user' \| 'page', detail?, avatar?, href? }`; only `id` and `label` are stored in the document.                                                                                                                                                          |
| `ai`            | `AIComplete`         | —       | The AI transport. With it, `/` gains **Continue writing** and **Ask AI**, and the selection bubble an **Improve** button; without it they are hidden. Signature: `(request, { signal }) => AsyncIterable<string>` — yield text chunks, and stop when `signal` aborts. Use `@richkitjs/ai-openai` or `@richkitjs/ai-anthropic`, or write your own. See [AI](/docs/ai). |
| `aiAuthor`      | `string`             | `'AI'`  | Author name recorded on AI-written text.                                                                                                                                                                                                                                                                                                                              |
| `footer`        | `ReactNode`          | —       | Below the status bar — a hint line, a save indicator.                                                                                                                                                                                                                                                                                                                 |

Swapping the `ai` function each render is fine (it is read through a ref); only switching
AI on or off rebuilds the editor.

### `DocxEditor`

A word-processor page: toolbar with zoom, bold/italic/underline/strike/code, lists,
to-do list, `.docx` import and export, print, and a theme toggle.

| Prop       | Type        | Default           | Description                                                              |
| ---------- | ----------- | ----------------- | ------------------------------------------------------------------------ |
| `title`    | `string`    | —                 | The document's title — shown above the page and used as the print title. |
| `filename` | `string`    | `'document.docx'` | Name of the file the export button downloads.                            |
| `brand`    | `ReactNode` | —                 | Shown opposite the title above the page — a logo or product name.        |

`value` stays HTML (or your `format`); `.docx` is only for import and export. For
converting on a server, use `@richkitjs/docx` directly — see
[Docx editing](/docs/usecases/docx-editing).

### `MarkdownEditor`

Rich editing on one side, the live Markdown source on the other. Typing in either side
updates the other. **`format` defaults to `'markdown'`** here, so `value` and `onChange`
are Markdown strings out of the box. Formulas are kept as `$…$` (inline) and `$$…$$`
(display); load the math styles to render them:

```tsx
import '@richkitjs/extension-math/style.css'
```

| Prop         | Type      | Default         | Description                                                       |
| ------------ | --------- | --------------- | ----------------------------------------------------------------- |
| `filename`   | `string`  | `'document.md'` | Name of the file the download button saves.                       |
| `showSource` | `boolean` | `true`          | Show the Markdown source pane. `false` leaves only the rich side. |

### `HtmlEditor`

Rich editing beside a live, editable HTML source pane. The source pane is read-only
while `disabled` or `readOnly` is set.

| Prop         | Type      | Default | Description                |
| ------------ | --------- | ------- | -------------------------- |
| `showSource` | `boolean` | `true`  | Show the HTML source pane. |

### `CommentsEditor`

Comment threads anchored to text, with a sidebar to reply and resolve. Select text and
use the toolbar or bubble-menu comment button. The threads live in the document as
marks, so they travel with `value` — save the value and the comments come back with it.

| Prop     | Type     | Default | Description                                                                       |
| -------- | -------- | ------- | --------------------------------------------------------------------------------- |
| `author` | `string` | `'You'` | Name new comments and replies are attributed to — pass the signed-in user's name. |

### `TrackChangesEditor`

Suggesting mode: insertions and deletions are recorded as suggestions, shown inline and
listed in a sidebar with accept and reject buttons. Suggestions are marks in the
document, so they travel with `value`.

| Prop           | Type      | Default | Description                                                                                   |
| -------------- | --------- | ------- | --------------------------------------------------------------------------------------------- |
| `author`       | `string`  | `'You'` | Name new suggestions are attributed to.                                                       |
| `trackChanges` | `boolean` | `true`  | Record edits as suggestions. `false` edits the document directly (existing suggestions stay). |

### `MentionsEditor`

A chat composer. <kbd>Enter</kbd> sends, <kbd>Shift+Enter</kbd> breaks the line, and
while the `@` menu is open <kbd>Enter</kbd> picks a person instead.

| Prop       | Type                     | Default | Description                                                                                                   |
| ---------- | ------------------------ | ------- | ------------------------------------------------------------------------------------------------------------- |
| `mentions` | `MentionCandidate[]`     | —       | Who and what can be mentioned after `@`. Same shape as `NotionEditor`'s.                                      |
| `onSubmit` | `(html: string) => void` | —       | Called with the message's HTML on Enter or the send button. The box then clears. Empty messages are not sent. |
| `header`   | `ReactNode`              | —       | Rendered in the bar above the message log — a channel name, a hint.                                           |
| `children` | `ReactNode`              | —       | The message log, rendered above the composer.                                                                 |

```tsx
<MentionsEditor
  header="#general"
  mentions={[{ id: 'u1', label: 'Ada Lovelace', detail: '@ada' }]}
  onSubmit={(html) => send(html)}
>
  {messages.map((m) => (
    <Message key={m.id} {...m} />
  ))}
</MentionsEditor>
```

### `CommentBoxEditor`

A reply box with a live character count and a post button.

| Prop          | Type                     | Default   | Description                                                                                                                                             |
| ------------- | ------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `limit`       | `number`                 | `280`     | Character limit. The count turns red past it and posting is blocked.                                                                                    |
| `onSubmit`    | `(html: string) => void` | —         | Called with the reply's HTML when posted. The box then clears. The button is disabled while the box is empty, over the limit, `disabled` or `readOnly`. |
| `submitLabel` | `string`                 | `'Reply'` | The post button's label.                                                                                                                                |
| `children`    | `ReactNode`              | —         | Rendered above the box — the thread being replied to.                                                                                                   |

### `FindReplaceEditor`

An editor under an always-open find and replace bar: match case, previous
(<kbd>Shift+Enter</kbd>) and next (<kbd>Enter</kbd>), replace and replace all.

| Prop                 | Type     | Default | Description                       |
| -------------------- | -------- | ------- | --------------------------------- |
| `defaultQuery`       | `string` | `''`    | What the find box starts with.    |
| `defaultReplacement` | `string` | `''`    | What the replace box starts with. |

### `AgentEditor`

A document with an "Ask the agent" dock. The user types an instruction; your function
drafts a section, which is appended to the end of the document.

| Prop       | Type                                                            | Default | Description                                                                                                                                                                        |
| ---------- | --------------------------------------------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `complete` | `AIComplete`                                                    | —       | A streaming AI transport, the same one [`@richkitjs/extension-ai`](/docs/ai) takes. The section streams into the document as the model writes it. Takes precedence over `onDraft`. |
| `onDraft`  | `(prompt: string, editor: Editor) => string \| Promise<string>` | —       | Returns the new section as HTML. Receives the live `editor`, so you can send the current document as context.                                                                      |

Without `complete` or `onDraft` the agent dock is hidden.

The quickest setup is `complete` with an adapter. Your server route holds the API key and
passes the model's stream through — see the
[`@richkitjs/ai-anthropic` server proxy](https://www.npmjs.com/package/@richkitjs/ai-anthropic):

```tsx
import { anthropicComplete } from '@richkitjs/ai-anthropic'

;<AgentEditor complete={anthropicComplete({ endpoint: '/api/ai' })} />
```

The model is asked for Markdown (the exact wording is exported as `agentDraftPrompt`),
which renders live as headings, paragraphs and lists. The finished section lands as a
single `onChange` and a single undo step. A **Stop** button cancels mid-stream, and a
failed stream shows its error in the dock and leaves the document untouched.

For full control over the model call, use `onDraft` instead:

```tsx
<AgentEditor
  onDraft={async (prompt, editor) => {
    const res = await fetch('/api/draft', {
      method: 'POST',
      body: JSON.stringify({ prompt, doc: editor.getHTML() }),
    })
    return res.text() // HTML
  }}
/>
```

For streaming, suggestion-based AI edits, see [Agent workflows](/docs/usecases/agent-workflows).

### `QuestionEditor`

A multiple-choice question: a stem, answer options, the correct answer and a point
value. The stem and each option are small rich-text editors that support formulas
(double-click a formula to edit it). It does **not** take the shared props — its value is
an object, so it has its own set.

```ts
interface QuestionValue {
  stem: string // HTML
  options: string[] // HTML each, one paragraph; the count sets how many rows render
  optionIds?: (string | number)[] // optional stable ids, parallel to options
  correct: number // index into options, or -1 when none is marked
  points: number
}
```

Formulas in the HTML are elements carrying their LaTeX, not `$…$` text:

```ts
const value: QuestionValue = {
  stem: '<p>Solve <span data-math="x^2 = 4"></span> for x &gt; 0.</p>',
  options: ['<p>1</p>', '<p><span data-math="\\sqrt{4}"></span></p>'],
  correct: 1,
  points: 1,
}
```

A display formula in the stem is `<div data-math-block="…"></div>`.

| Prop            | Type                             | Default                             | Description                                                                             |
| --------------- | -------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------- |
| `value`         | `QuestionValue`                  | —                                   | Controlled value.                                                                       |
| `defaultValue`  | `QuestionValue`                  | empty question                      | Uncontrolled starting value.                                                            |
| `onChange`      | `(value: QuestionValue) => void` | —                                   | Called with the whole question after any edit — stem, option, correct answer or points. |
| `onBlur`        | `() => void`                     | —                                   | Focus left the question.                                                                |
| `name`          | `string`                         | —                                   | Hidden input holding the value as JSON.                                                 |
| `disabled`      | `boolean`                        | `false`                             | Not editable, styled as disabled.                                                       |
| `readOnly`      | `boolean`                        | `false`                             | Not editable.                                                                           |
| `label`         | `string`                         | `'Multiple choice · single answer'` | Shown above the question.                                                               |
| `hint`          | `string`                         | usage hint                          | Shown below the options.                                                                |
| `theme`         | `'light' \| 'dark'`              | `'light'`                           | Colour scheme.                                                                          |
| `className`     | `string`                         | —                                   | On the root element.                                                                    |
| `style`         | `CSSProperties`                  | —                                   | On the root element.                                                                    |
| `onEditorReady` | `(editor: Editor) => void`       | —                                   | The stem's `Editor`, once mounted.                                                      |

Its `ref` is a `QuestionEditorHandle`: `{ editor, focus(), getValue() }`, where `editor`
is the stem's editor.

It needs the math styles as well:

```tsx
import '@richkitjs/extension-math/style.css'
```

## Styling

`@richkitjs/editors/style.css` styles everything the editors render. Every colour,
radius and shadow comes from CSS custom properties, so restyling is overriding
variables — no need to fight selectors.

### Theme variables

| Variable                                               | Light default         | Used for                                        |
| ------------------------------------------------------ | --------------------- | ----------------------------------------------- |
| `--rk-bg`                                              | `#f5f6f8`             | Frame and toolbar background.                   |
| `--rk-surface`                                         | `#ffffff`             | Panels, menus, popovers, dialogs.               |
| `--rk-surface-2`                                       | `#f0f2f5`             | Hover and pressed backgrounds.                  |
| `--rk-border`                                          | `#e3e6ea`             | Borders and dividers.                           |
| `--rk-border-strong`                                   | `#d0d4da`             | Input borders, emphasised dividers.             |
| `--rk-text`                                            | `#1a1d21`             | Body text.                                      |
| `--rk-text-muted`                                      | `#5b6470`             | Secondary text, hints, counts.                  |
| `--rk-accent`                                          | `#2563eb`             | Active buttons, links, focus rings.             |
| `--rk-accent-soft`                                     | `rgba(37,99,235,.12)` | Active-button and selection tint.               |
| `--rk-accent-hover`                                    | `#1d4ed8`             | Accent on hover.                                |
| `--rk-danger`                                          | `#dc2626`             | Errors, destructive actions, over-limit counts. |
| `--rk-radius`                                          | `8px`                 | Frames and panels.                              |
| `--rk-radius-sm`                                       | `6px`                 | Buttons and inputs.                             |
| `--rk-radius-lg`                                       | `12px`                | Dialogs and large cards.                        |
| `--rk-shadow-sm` / `--rk-shadow-md` / `--rk-shadow-lg` | —                     | Elevation of toolbars, popovers and dialogs.    |

The variables are prefixed with `--rk-` so they never collide with your app's own
tokens. Before 0.3 they were unprefixed (`--bg`, `--surface`, `--accent`, …); if you
override them, add the prefix: `--accent` becomes `--rk-accent`.

The light values sit on `:root` and `[data-theme='light']`; `[data-theme='dark']`
redefines the colour ones. Each editor puts `data-theme` on its root element from the
`theme` prop, so override per theme like this:

```css
/* Your brand colour everywhere */
:root,
[data-theme='light'] {
  --rk-accent: #0f766e;
  --rk-accent-soft: rgba(15, 118, 110, 0.12);
  --rk-accent-hover: #115e59;
}
[data-theme='dark'] {
  --rk-accent: #2dd4bf;
}
```

Or scope an override to one editor through `className` or `style`:

```tsx
<MinimalEditor
  className="my-editor"
  style={{ height: 480, '--rk-radius': '0px' } as CSSProperties}
/>
```

Inside every editor, the document itself is `.editor .ProseMirror` — style content
(headings, paragraphs, tables) there. The toolbar uses the shared `@richkitjs/react`
classes (`.toolbar`, `.tb-group`, `.tb-btn`, `.is-active`), so one rule restyles every
editor's buttons. The frames use `box-sizing: border-box` whatever your page uses.

### Height

Frames grow with their content. To fix a height and scroll inside, set it on the root:

```tsx
<NotionEditor style={{ height: '70vh' }} />
```
